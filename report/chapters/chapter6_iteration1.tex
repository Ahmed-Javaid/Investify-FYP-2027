\section{Data Structures, Algorithms and Code Conventions}
The implementation keeps records indexed by session inside a source/digest-bound collection. Feature/probability/SHAP mappings retain named keys; ranked contribution objects preserve magnitude, value and direction. Context materializes JSON-safe feature rows without replacing absent inputs with neutral observations. Frozen plans and receipts use explicit SHA256 relationships rather than model-name assumptions.

The live checking algorithm is: validate the selected record; construct maintained context; read the current candidate and canonical facts; verify visible and structured claims independently; retain any rejected report; render and independently verify fallback; display only a result whose case/text identity still matches. The profile algorithm validates eight answers, computes weighted capacity/caps and tolerance, reconciles the smaller score, then scores only held-out comparator sessions using earlier scaling statistics. Neither algorithm updates the classifier.

New UI functions use snake-case names, explicit page/step registries and small functions named for user actions. Data-boundary docstrings state their no-training/no-write role. Syntax/AST checks and focused UI tests are engineering static/dynamic evidence; the group must still explain and modify its actual owned functions during review. The source/file walkthrough is supplied separately rather than replaced with programming listings in the report.

\section{Mechanism of the Fresh Calibration Collapse}
Both fresh modes share the same clipped isotonic maps. Buy's global output minimum is 0.5344828, while Hold and Sell never exceed 0.2500000 and 0.3139535. Buy therefore leads by at least 0.2205293 before normalization. Linear interpolation with clipped endpoints stays within these bounds. Dividing every output by the same positive sum preserves argmax: these maps force Buy for every valid raw probability vector.
