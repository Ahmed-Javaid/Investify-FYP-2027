\chapter{Testing and Early Validation}
\section{Testing Strategy}
Positive acceptance and labelled corruptions are both tested. Actual saved decisions support integration checks. Missing-input and corruption fixtures are test inputs, not synthetic substitutes for historical news or real LLM generations.
\section{Test Levels and Techniques}
Unit checks cover claim/schema validation, strict mode and fallback. Integration checks cover all 372 records. Local HTTP checks exercise the actual server and verification endpoint. Separate Streamlit AppTest cases exercise real widgets when its runtime is installed \cite{streamlit_apptest}.
\section{Test Cases}
Important cases include correct JSON beside wrong displayed confidence/direction/value/class, correct prose beside wrong JSON, omitted essential claims, malformed/non-finite payloads, padding around a contradiction, unsupported sentences, and missing data/runtime. The appendix maps groups to requirements.
\section{Test Results}
On 12 October 2026, the selected suite completed with \textbf{149 passed and zero skipped}, including 15 actual Streamlit AppTest cases. All 372 records retain schema/context/numeric-template and complete-guided-template acceptance. The live HTTP run passed 62 checks, including explanation and separate risk/refusal probes. The comparator audit passed 228 arithmetic/chronology/immutability checks on 76 actual held-out rows and three labelled profile scenarios. Runtime/source hashes and duration are in evidence JSON. This is not the complete scientific suite, a participant study or predictor-performance evaluation.

The default-mode fixture study has 112 cases: 80 corruptions rejected, 16 clean cases accepted, 16 vague-sentence cases accepted, and zero clean cases rejected. Vague-sentence acceptance remains a rate-threshold limitation. Strict mode rejects unsupported sentences but restricts accepted prose to the supported grammar.
\section{Acceptance Testing / Validation}
Programmatic acceptance is demonstrated for the explanation and prototype-comparator paths, including actual Streamlit widgets and HTTP health. Browser visual QA, participant comprehension and remote GitHub CI remain pending. No participant observations or member authorship are assumed.

The Social Study view's complete/partial flows are also exercised with clearly labelled benchmark/run fixtures: complete data exposes metrics and downloadable evidence; failed outcomes retain coverage/errors and refuse a paired comparison. Those widget tests do not establish actual sentiment-model quality.
\section{Edge and Failure Cases}
Correct JSON cannot hide empty text, an omitted decision or missing notice. Invalid claim structure selects verified fallback. Missing/zero feature evidence is preserved; non-finite authoritative probabilities or attributions are rejected. Missing records return errors; absent training inputs disable re-runs. The local adapter's unavailable-provider, malformed/truncated output and retry/fallback paths are tested with labelled fixtures. Incomplete profiles, development-date comparator requests and missing technical inputs are refused. Actual-model behaviour still requires real generations.
\section{Defects and Corrective Actions}
New regressions reproduced payload-over-prose acceptance, unchecked feature values/target class, payload-supplied display coverage, and dilution by repeated correct claims. Independent checking and hard gates correct these defects. The old test requiring correct JSON to override wrong prose was replaced with the corrected regression. Rejection reporting now retains the failed candidate's metrics instead of showing fallback success as the rejection reason.
