\chapter*{Executive Summary}
\addcontentsline{toc}{chapter}{Executive Summary}
Investify (F26-003-Investify) aims to help a retail user understand a one-week educational Buy/Hold/Sell view and its evidence. A label alone does not communicate which inputs affected a model, whether conflicting evidence exists, or what the prediction establishes. Explanations introduce another risk: fluent text may contradict its underlying facts. The project separates the learned predictor, recorded evidence, user-facing explanations and checking.

The baseline is a historical NVDA news/technical experiment, with FNSPID and supplemental Alpaca/Benzinga artifacts. It includes exchange alignment, technical/news features, fixed XGBoost evaluation, calibration, a linear comparator, TreeSHAP, a template and verifier. It is narrower than the full proposed multi-equity, social/risk-conditioned product. Both saved calibrated evaluation folds output Buy for all 186 sessions, so useful stock prediction has not been demonstrated.

The current increment covers all five technical and six news features, including values, attributions, meanings and coverage limitations. It corrects a reproduced defect in which correct JSON could conceal incorrect visible prose. Both representations are now checked independently. Essential visible facts are required, known contradictions always fail, and strict mode rejects unsupported sentences. Candidate rejection reports remain separate from the verified fallback report.

The portable interface uses standard Python and actual saved records. The restored Streamlit interface also executes verification/fallback, invalid-input and missing-re-run states, and a Social Study readiness/comparison view. Twelve actual AppTest cases pass in an isolated E: viewer environment. Browser visual review and remote Windows/Linux CI execution remain unverified.

A local, explicitly configured LLM can now request JSON-schema output containing supported factual sentences and exact maintained feature definitions. The adapter retains raw output, served/requested model identifiers, failed attempts, timing and verification. It retries at most twice for bad output and fails fast on provider unavailability, then emits a verified definition-enhanced deterministic explanation. Its tests use labelled provider fixtures. The actual service/model is unavailable, so these tests establish integration behaviour rather than language-model quality.

The frozen pilot protocol divides each saved corpus chronologically into development and held-out records and compares numeric template, complete-guided template and real generations. All feature values/contributions/directions, family totals, meanings and attribution scope must appear correctly in both guided representations. Initial failures are retained; a blocked provider receives no invented quality score. The selected suite has 124 passes and no skips; all 372 records/guided templates and 62 live HTTP checks pass.

The prototype risk profile requires all five capacity and three tolerance answers, exposes project caps and uses the smaller score. A separately declared linear comparator scales the first 148 saved raw-feature rows per corpus and scores only the later 38. Its blend weight depends on the profile and is compared with R=0.5; the classifier remains unchanged. The audit passes 228 real-row/labelled-scenario arithmetic checks. The mapping is unvalidated for suitability or prediction, and no outcome labels or return metrics are available.

The panel's requested problem/contribution, model inventory, metrics, transparency and domain clarification are reflected in working material. Primary-source research now distinguishes sentiment classification, data integration, attribution and record consistency. Research novelty, human comprehension and complete proposal-action closure still require further evidence and review.

The main remaining dependencies are a working model, scientific environment/raw inputs, current repository access, human social annotations, approved risk semantics, actual member contributions and a confirmed assessment date. QLoRA/teacher comparison, broader ticker/horizon work, deployment and participant acceptance remain later activities. Institutional metadata/signatures, report compilation and visual verification are unfinished; this draft is not submission-ready.
