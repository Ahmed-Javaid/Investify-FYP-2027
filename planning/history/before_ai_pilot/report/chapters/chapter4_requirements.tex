\section{User Interactions / Use Cases}
The increment lets a reviewer select a historical corpus/session, inspect all technical/news evidence, check explanations, inspect rejection/fallback, complete an explicit prototype risk profile, and compare a separate profile-dependent linear blend. It identifies absent social features, historical data, unchanged classifier probabilities and constant-Buy behaviour. The final retail-user journey remains broader than this demonstration.

\section{Detailed Use Cases}
For Check Explanation, the precondition is an available, validated record. The user submits visible text and optional JSON claims. Both are checked against the record. A contradiction, missing essential display claim, malformed payload, or unsupported sentence in strict mode causes rejection and a verified deterministic fallback. An unavailable record produces an explicit error instead of a substituted decision.

\section{Non-Functional Requirements}
\subsection{Reliability}
Missing inputs do not produce invented decisions. A template failing its own verifier raises an error. The portable server calls the real pipeline rather than simulating generation.
\subsection{Usability}
Candidate and emitted text are labelled separately. Feature meanings, raw-score attribution units, and unsupported capabilities are disclosed. Visual QA and participant comprehension checks remain pending.
\subsection{Performance}
Interactions perform no training or corpus scoring. HTTP duration is recorded in the live evidence JSON; it is not a browser-rendering or full-system latency measurement.
\subsection{Security}
The portable server binds to loopback and serves a single page and explicit APIs. It does not expose arbitrary project files or provide brokerage access, authentication, or production deployment.
\section{Acceptance Criteria}
Both corpora retain their recorded facts and accepted templates. Correct JSON cannot hide wrong visible prose; correct prose cannot hide wrong JSON. Rejection yields the verified template and retained failed report. Missing inputs are disclosed without synthetic replacement. Strict mode rejects unsupported sentences while preserving correct templates.
