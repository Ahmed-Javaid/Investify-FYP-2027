## Failure cases to explain

| Trigger | Required response and boundary |
| --- | --- |
| Wrong visible number beside correct JSON | Candidate rejection and a separately checked fallback. JSON correctness cannot certify displayed text. The reverse contradiction is also checked. |
| Missing/invalid saved record | Explicit error; no substitute stock decision. HTTP returns a client error for an unknown session. Test fixtures demonstrate invalid-record handling; do not corrupt research artifacts for a live demonstration. |
| Unsupported prose in strict mode | Rejected by the maintained grammar. Default mode can accept a small number of vague claims below its rate threshold; the 112-case historical fixture matrix includes 16 accepted vague corruptions. This is a known limit, not arbitrary-language verification. |
| Unconfigured explainer | Explicit deterministic guide and no provider request. Failed/truncated provider attempts are retained by the adapter; those paths currently have fixture evidence, not successful real student inference. |
| Incomplete profile or development session | Refuse a comparator decision. Changing the selected record cannot leave a stale comparator result. |
| Missing/empty/truncated/read-denied scientific files | Disable re-run and identify blockers. Structural preflight does not load rows, establish cache completeness or validate installed versions against the scientific lock. |
| Missing or invalid teacher evidence | No training downloads; failure is visible. Preserved evidence must not be edited to demonstrate this. Actual widget tests use labelled fixtures/mocks. |
| Missing/partial candidate outputs | No paired winner or manufactured neutral prediction. Study metrics remain null until genuine required outputs exist. |

## Code and scientific questions

**What does the language model decide?** The decision engine records Buy/Hold/Sell. The language model explains that record; it does not choose stock actions. The current teacher supplies examples for the planned small explainer. A saved teacher example is not a live student model.

**Why verify prose and JSON separately?** The user reads prose. Earlier payload-first checking could accept a wrong displayed probability beside correct JSON. `verify` parses both, derives required coverage from visible text, uses the worse numerical/directional fidelity, and treats known contradictions as hard failures. `emit` retains rejected-candidate evidence while verifying fallback separately. Study outputs must score raw candidate behaviour as well as emitted output.

**What does SHAP mean here?** The stored base value plus all feature attributions reconstructs the selected class's raw model score. The top five contributors are a magnitude-ranked subset. Positive attribution supports that class's raw score; negative opposes it. This is different from a feature value's sign. The values do not sum to calibrated probability and do not prove what caused a market move. Family totals use all family features, not just the top five.

**What does sentiment mean?** FinBERT polarity is P(positive) minus P(negative) on headlines. Headline count measures news attention, not traded share volume. `dispersion` is variation of session-average polarity, not disagreement among individual headlines. The separate MSFT social reference pilot cannot establish NVDA social transfer or predict returns. AI-reference agreement is not independently human-validated accuracy; only two negative held-out references make recall coarse.

**Does R mean conservatism?** The profile reconciles project capacity/tolerance scores with the smaller score. The comparator uses C(R)=T+R(S−T), so R weights news against technical evidence. A smaller R does not guarantee a more conservative action. These stand-in questions/caps are unvalidated, lambda=2.25 is not implemented, and no suitability or financial outcome study exists. The profile's financial time horizon is distinct from the predictor's five-session horizon.

**Why all Buy?** That is the measured saved class distribution. Only predicted-class raw margins are retained. The preserved historical implementation transferred calibration mappings across separately fitted classifiers; that transfer remains unchecked and is not a proved cause of constant-Buy output. Current source instead defaults to a frozen classifier/scaler and offers an explicit refit-transfer comparator, both with corrected label/calibration availability. Their fixture checks are not genuine fitted-model results. Restore original inputs and compare the current modes while retaining the historical baseline separately. Do not tune held-out action thresholds to manufacture variety.

**What does the teacher pilot establish?** Six actual prose outputs pass a bounded checking contract; factual JSON is assembled separately as hybrid supervision. The teacher and guide have the same sentence-line multisets, reordered. No extra explanatory content, comprehension benefit, adequate training size or Hold/Sell generalisation is established. Training/validation/test are date grouped; test inputs are excluded. Student inference and QLoRA remain pending and QLoRA is outside the original first-mid prerequisite.

**What is the team's contribution?** The working contribution is the point-in-time evaluation controls and record-grounded explanation checking/fallback, with scoped evaluation and failure disclosure. FinBERT, XGBoost, TreeSHAP and publisher student weights are external components. A research novelty/advantage claim still needs a fair closest-work comparison and actual studies. Each student must explain code they reviewed and disclose tool assistance accurately; this guide does not assign authorship or certify comprehension.
